## 文書の状態

- 対象：地域住民NPCの会話・案内・表示に関する最小実装

## 目的

プレイヤーがゲーム中に困ったとき、地域住民NPCとの会話から土木知識と地域の過去を知り、その情報を土木技術の選択・活用に役立てながら楽しく学べる状態を作る。

NPCは正解や最適な配置場所を断定せず、判断材料を提供する。プレイヤー自身が地形、予算、残り時間、NPCから得た情報を組み合わせて判断する。

## 既存仕様との関係

本書は [`requirements.md`](./requirements.md)、[`detailed-design.md`](./detailed-design.md)、[`dialogue-ai-design.md`](./dialogue-ai-design.md) を前提とするMVP決定記録である。

MVPでは、次の項目について既存の案より本書を優先する。

- 会話開始時の距離判定は行わず、俯瞰マップ上のNPCアイコンをどこからでもタッチして会話を開始する
- 質問はNPCごとの選択肢3件だけとする
- 一般住民がレベル3の情報を直接提供できない場合は、詳しい住民を案内する

本書は体験上の合意を記録する。今回実装したソロ用RESTと型の契約は [mvp-api.md](./mvp-api.md) に記録し、将来のゲームサーバー統合契約はAPI設計Issueで扱う。

## MVPのNPC構成

現在の最小プレイ構成は8人の固定NPCで開始する。住民3人と、5つの治水技術を担当する工事系の経験者5人を配置し、いずれもマップ内で暮らす人物として扱う。

| 種別                     | 役割                                         | 提供する情報                                                                              |
| ------------------------ | -------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 一般の地域住民           | 地域で暮らす中で得た経験を伝える             | 地域の過去、過去の災害、土地や水の様子。レベル3では詳しい住民を案内する                   |
| 経験者・職業人の地域住民 | 河川・水路・土木工事などに関わった経験を持つ | 地域の経験に加え、土木技術の基本と使いどころ。レベル3では候補となる技術と注意点を説明する |

MVPで手応えを確認した後、同じデータ構造・会話設計を使って地域住民NPCを増やす。

## 段階ヒントと案内

各NPCは人物像に応じた質問候補を3件持つ。回答は同じ質問について段階的に詳しくする。

| レベル | 一般の地域住民                       | 経験者・職業人の地域住民                     |
| ------ | ------------------------------------ | -------------------------------------------- |
| 1      | 地域で見聞きした災害・土地の様子     | 経験や地域の様子を交えて話す                 |
| 2      | 一般的な防災・土木の考え方           | 技術の仕組みや役割をやさしく話す             |
| 3      | 詳しい住民の名前といる場所を案内する | 候補となる土木技術の使いどころ・注意点を話す |

レベル3でも、最適な配置座標や唯一の正解を断定しない。案内を受けた場合は、地図上の対象NPCが分かるようにする。

## 地図上の表示と会話UI

- NPCはマップ内の固定位置に表示する。最初は仮のテスト位置を設定データで管理し、後から実在地域・役割に合う地点へ差し替える
- 表示は人物アイコン、名前、短い肩書きとする。一般住民と経験者は、人物アイコンに小さな印を加えて見分けられるようにする
- NPCのアイコンまたは表示名をタッチすると、距離にかかわらず会話パネルを開く
- 会話パネルには、名前、肩書き、短い自己紹介、質問候補3件、閉じる操作を表示する
- 質問を選ぶと回答を表示し、レベル1・2では「もっと詳しく聞く」を表示する
- 会話中の質問・回答はパネル内に残し、閉じた時点で破棄する

## 知識データとローカルLLM

最初のUI動作確認では、仮の質問・回答文を使用する。その後、実在地域に関する情報は国土交通省、福島県、郡山市などの公的資料に限定して作成する。

選択式の質問候補から対応する承認済みFactを取得し、取得したFactだけをLLMへ渡す。これは固定質問に対する最小の検索拡張であり、自由入力・ベクトル検索・実行時URL巡回は行わない。

ローカルLLMにはOllamaを使用する。今回のMVPでは、根拠と人物像に沿って登録した言い回しの候補から選択させる。任意の文章を生成して事実を補完する方式ではない。接続失敗、タイムアウト、出力検証失敗時は同じ知識に対応する固定回答を表示する。

開発初期の共有確認では、1台の開発PCでGo・Web・Ollamaを起動し、同一LANの他の開発者はそのWebへアクセスする。Ollamaは外部へ直接公開せず、Goサーバーだけが接続する。インターネット公開用の共有AI Backendは別途検討する。

## 出典と承認

- NPCの実データは、質問候補、根拠となる事実、出典URLをセットで提示し、ユーザーの承認後に利用する
- NPCがゲーム中に使用した情報の出典は、結果画面で確認できるようにする
- LLMの一般知識、実行時Web検索、未承認の情報を根拠として使用しない

## MVPの対象外

- ベクトル検索や実行時URL巡回を行う高度なRAG
- 自由入力と検索型RAG
- インターネット公開用の共有AI Backend、クラウドLLM、自動フェイルオーバー
- 3Dアバター、表情アニメーション、音声
- NPCの移動、自動接近、施設配置
- 会話履歴の永続保存
- 実行時のWeb検索

## 今回の実装で決めた事項

- 対象は既存の阿武隈川・郡山シナリオ。8人は施設配置可能域の外の仮固定位置に置く
- NPCは、水害記録・土地の高低・雨量と水位を担当する住民3人と、堤防・護岸・遊水地・排水機場・河道掘削をそれぞれ担当する経験者5人。人物像・座標・各3問・段階回答は `packages/game-data/npc/npc-catalog.json` で管理する
- ユーザー提供のリサーチを基に、一次資料と照合した12件を登録した。採用範囲と留保は [照合記録](./research/verification-notes.md) に記録する。外部専門家による監修済みという意味ではなく、会話の内容・難易度はプレイ確認で調整する
- ローカルモデルは Ollama の `qwen3:14b`。接続できない場合は固定回答を使う。起動手順は [動作確認ガイド](./prototype-playtest.md) を参照
- 今回は [NPC REST API](./mvp-api.md) を使う。ゲーム状態の完全なサーバー権威化は対象外だが、同一LANでは1台のGoサーバーとOllamaを共有して複数開発者がNPCを試せる
