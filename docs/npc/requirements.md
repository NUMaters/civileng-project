## 1. 文書目的

CivilCraft に追加する「地域情報提供型・住民 NPC」機能について、実装方法を規定せず、満たすべき要件を一意な ID とともに定義する。承認後、詳細設計・実装の基準として用いる。

## 2. 背景と機能目的

土木・治水の知識がないプレイヤーに、地域の災害・環境・土木技術に関する予備知識を与える。NPC は正解を直接指示せず、プレイヤーは得た情報・地形観察・残り時間・予算を組み合わせて自分で判断する。会話は任意で、時間とのトレードオフとして扱う。

## 3. 対象ユーザー

主対象は小学校高学年。短く分かりやすい標準語、難しい漢字の回避またはふりがな付与を基本とする（詳細は 15 章）。

## 4. スコープ

- 地域住民 NPC の表示・接近判定・会話（質問候補／自由入力）
- 段階ヒント（レベル 1〜3）
- 準備フェーズの LLM（Ollama）による事実の言い換え
- 災害フェーズの定型文応答
- 結果画面での出典表示
- 匿名分析データの記録・CLI 出力
- プレイヤー単位の「よみやすさ」設定（かな中心／ふりがな／標準）

## 5. スコープ外

AI ディレクター、災害強度・発生タイミングの自動調整、津波・地震等の既存コア外災害、NPC の移動・避難・施設配置、音声・音声合成、3D 表情アニメーション、会話共有ボタン、会話の永続記憶、災害中の LLM 文章生成、実行時 Web 検索、複数クラウド LLM の自動フェイルオーバー、認証なし分析データ公開 API、質問・回答本文の保存、NPC 利用によるスコア加減点、最適配置の直接回答、NPC 以外の画面への「よみやすさ」適用。

## 6. 用語定義

| 用語 | 定義 |
|---|---|
| 承認済み知識 | 人間が公的資料から作成・承認した `canonicalFact` を持つレコード（`approved = true`） |
| ヒントレベル（hintLevel） | 段階ヒントの深さ（1〜4、4 は提供禁止）。正解到達の難易度に関わる |
| よみやすさ（readingLevel） | かな中心／ふりがな／標準の 3 段階。表記（文字種・ふりがな付与範囲）のみを変える設定で、事実・情報量・ヒントレベルとは無関係 |
| セグメント | 本文を構成する最小単位（文字列＋任意の読み仮名＋表示制御フラグ）。具体的な型・パッケージ配置は [`detailed-design.md`](./detailed-design.md#8-表示用データ構造) を正本とする |
| 承認済み文言 | NPCの表示名・職業表示、質問候補・自己紹介・災害中定型文・フォールバックのように、文言そのものが人間承認を経て確定しているセグメント配列 |
| 実行時生成回答 | 承認済みの `canonicalFact` を根拠に LLM が実行時に生成し、サーバー検証を通過した回答。根拠となる事実は承認済みだが、生成された文言自体は人間の事前承認を経ていない |
| グロッサリー | 技術用語・地名・NPC が頻繁に使う語の読みを人間が承認した一覧。詳細は [`dialogue-ai-design.md`](./dialogue-ai-design.md) を参照 |

## 7. 利用シナリオ

- プレイヤーがロビーで「よみやすさ」を選び、準備フェーズで NPC に接近し質問候補から選択、回答を得て施設配置の判断材料にする。
- 災害フェーズで NPC に再度話しかけ、周辺の浸水状況を短く確認する。
- 結果画面で参照した情報の出典を確認する。

## 8. NPC の役割

マップ内の家・集落にいる地域住民。名前・職業・簡単な性格を持ち、担当テーマ外には回答しない。自ら移動・接近しない。役割テンプレートは次の3種を基本とする。

| 役割 | 主な知識 |
|---|---|
| 長年住んでいる住民 | 過去の洪水、浸水時の経験、地域の変化 |
| 農家・土地に詳しい住民 | 低地、水がたまりやすい場所、土地や水の流れ |
| 元建設業者など | 堤防、排水機場などの土木技術の一般的な役割 |

NPC の正確な人数はマップ完成後に決定し、コードへ固定しない。名前・性格・自己紹介・質問候補は実装時に Claude Code が仮案を提示し、ユーザーが承認した内容だけをマスターデータへ登録する。

NPC には次の共通特性がある。

- 名前、職業、簡単な性格を持つ
- 職業・経験に応じて話し方を少し変える
- フィールド内の決められた位置から移動しない
- プレイヤーへ自分から接近しない
- 施設を配置しない
- プレイヤーが接近し、明示的に話しかけた場合だけ会話する
- 自宅または周辺地域に関係する情報だけを持ち、担当テーマ外の内容は回答しない

NPC の数・座標・会話可能距離・建設禁止範囲は、シナリオ・マップごとのマスターデータで管理する。NPC の位置はマップ上に常時アイコンで表示する。NPC は家または役割と関係する地点に配置し、固定 NPC が深い水中に立つ不自然さを抑えるため、極端に浸水しにくい地点へ配置する。NPC・自宅・会話範囲には施設を配置できず、この制限はクライアント側の入力制御に加えサーバー側でも検証する。

## 9. フェーズ別動作

| フェーズ | NPC の状態 | 会話内容 |
|---|---|---|
| ロビー | 出現させない | 会話不可 |
| 準備 | フィールド上に出現 | 地域情報、過去の災害、地形、土木技術について聞き取り可能 |
| 災害 | 同じ位置に留まる | NPC 周辺の現在の災害・浸水・住宅・道路の状況を短く伝える |
| 結果 | 会話不可 | 結果画面で参照した地域情報と出典を確認可能 |

**準備フェーズから災害フェーズへ移行した時に、当該ゲームセッション内で準備中の会話画面を自動的に閉じ、未完了の LLM 回答を破棄する。** プレイヤーが災害中に再度話しかけた場合は、災害中の現在状況を表示する。

NPC 機能を有効にしても、既存の準備フェーズの時間（60 秒）を変更しない。NPC との会話によってゲーム時間を停止・延長しない。準備時間を将来調整する場合は、既存ゲーム側のマスターデータ（`packages/game-data/rules/game-timing.json` 等）で行い、NPC 機能側で独自に管理しない。

## 10. 会話の開始・終了

プレイヤーが NPC の会話範囲へ近づくと「話す」ボタンが表示される。タップすると、プレイヤーの移動と施設配置を停止したうえで NPC の会話パネルを表示する。ゲーム時間と他プレイヤーの行動は継続する。会話パネルには、NPC の名前・職業・短い自己紹介・質問候補3件・自由入力欄（最大100文字）・閉じるボタンを表示する。プレイヤーが閉じるボタンをタップすると会話を終了し、移動と施設配置を再開する。会話画面を閉じた時点で、その会話セッションの履歴を破棄する。会話画面を開いている間はプレイヤーが移動できないため、会話中に接近距離を繰り返し判定しない。

会話操作には次の制御を適用する。

- 回答待ち中は質問送信を無効化する
- 1 プレイヤーにつき同時に処理する質問要求は 1 件までとする
- 二重タップによる重複要求を拒否する（要求の対応付け方式は API 設計 Issue で決定する）
- 回答表示後 2 秒間は次の送信を受け付けない
- 範囲外・不適切・根拠なし回答の後には質問候補を再表示する
- 接続切断、ゲーム終了、フェーズ変更のいずれかが発生した場合も会話セッションを終了する

NPC は 1 人につき 1 つの担当テーマを基本とする。

## 11. 質問候補と自由入力

NPC ごとに質問候補 3 件を事前登録し、それぞれ承認済みの知識情報 ID と対応付ける。質問候補自体を LLM で動的生成しない。自由入力は最大 100 文字とし、地域・災害・地形・担当する土木技術に関する追加質問を受け付ける。NPC の地域・シナリオ・担当テーマで検索範囲を制限し、担当範囲外の質問には回答しない。ゲームと無関係または不適切な質問には「その話には答えられない」と短く返す。回答後、回答可能な質問候補を再表示する。

準備フェーズでは、正常に受理され、かつ承認済みの根拠情報が取得できた質問について、事前登録された質問候補と自由入力のいずれでも、回答文の言語化に毎回 LLM を使用する。範囲外・不適切・根拠なしと判定された質問、および LLM 障害時のフォールバックには、承認済みの定型応答を使用する。根拠が存在しない状態で、LLM の一般知識を使用して回答を生成してはならない。ただし取得経路は異なる。登録質問では、対応付けられた承認済み知識 ID を直接取得して LLM へ渡す。自由入力では、承認済み知識を RAG 検索した結果を LLM へ渡す。いずれの経路でも LLM は承認済み `canonicalFact` の言語化だけを行い、事実を追加しない。災害フェーズ中は LLM を使用しない。

## 12. 段階ヒント

ヒントは段階的に提供し、最初から具体的な正解を教えない。

| レベル | 内容 | 例 |
|---|---|---|
| 1 | 地域固有の観察・経験 | 「この辺りは、前の大雨で水が来たんだ」 |
| 2 | 一般的な技術知識まで | 「堤防は、川から水があふれるのを防ぐものだよ」 |
| 3 | 使用する技術の推薦 | 「このような洪水には、堤防が役立つかもしれないよ」 |
| 4 | 正確な配置場所の指定 | 提供しない |

レベル 3 のボタンは「もっと詳しく聞く」を 1 回使用した後に表示する。レベル 3 は元建設業者など、技術知識を持つ NPC だけが提供する。一般住民の場合は、技術知識を持つ NPC の場所を案内する。具体的な座標や最適配置を示すレベル 4 は禁止する。同じ質問を繰り返した場合、同じ事実を別の表現で回答する。質問回数にゲーム上の上限は設けない。

## 13. 災害中の応答

災害中は RAG による過去情報の長い聞き取りを行わず、NPC 座標周辺のサーバー権威型ゲーム状態から、現在の状況を短く伝える。使用する状況は、発生中の災害種別、NPC 周辺の浸水有無、浸水の深さまたは被害段階、水位の上昇・維持・低下、NPC の家・周辺道路の浸水有無である。被害表現には、家の前まで水が来ている・床下床上浸水・周辺道路の浸水・住宅所有物への軽度な被害・状況に応じた心配や不安を含め、NPC 本人のけが・死亡・家族の生命危機・過度な恐怖表現は含めない。MVP ではゲーム状態と承認済み定型文を対応させ、LLM は使用しない。

## 14. 結果画面

結果画面には、そのゲーム中に NPC 回答で参照された、参照した地域情報のタイトルまたは短い要約、公的資料の名称、出典 URL または資料識別情報を表示する。質問文・回答文は永続化せず、参照した `sourceId` のみをゲームセッション中に一時的に保持し、結果画面表示時にそこから承認済み出典メタデータを取得する。ゲームセッション終了後は一時保持した参照情報を破棄する。結果画面への配信方式（別のAPI設計Issueで決定）、および一時保持の設計詳細は [`detailed-design.md`](./detailed-design.md#20-結果画面への出典情報配信) を参照。質問文・生成された回答文は保存・再表示しない。プレイヤーは出典を見なくても結果確認を完了できる。

## 15. よみやすさ設定

- 3 段階：かな中心／ふりがな／標準。標準は既存設計（3章、小学校高学年向け）のデフォルトを踏襲する。
- **同一の基準本文（セグメント配列）を 3 段階で共有する。** レベルごとに異なる文章を用意しない。変わるのは表示方法（ルビの有無・漢字/読み仮名の切替）のみ。基準本文は、質問候補・自己紹介・災害中定型文・フォールバックのような**承認済み文言**の場合と、承認済み`canonicalFact`を根拠にLLMが実行時生成しサーバー検証を通過した**実行時生成回答**の場合があり、後者の文言自体は人間の事前承認を経ていない（6章「用語定義」参照）。
- LLM 回答も同様に、レベルごとに生成し直さない。**同一の LLM 出力をサーバー側で一度だけセグメント化し、クライアントの表示切替のみで 3 段階に対応する。** 表示中にプレイヤーがレベルを切り替えても、LLM の再実行や回答内容の変更は発生しない。
- 対象文言：LLM 生成回答、承認済みマスターデータ（NPCの表示名・職業表示・質問候補・自己紹介・災害中定型文・フォールバック）、フロントエンドの静的 UI ラベル（「話す」「閉じる」「もっと詳しく聞く」等）。NPCの性格はLLMへの内部指示として扱い、プレイヤーへ直接表示しないため、よみやすさ設定の対象外とする。
- 設定単位：本実証ではプレイヤー単位＝ブラウザクライアント単位とする（1 台のスマートフォン／1 ブラウザを 1 プレイヤーとして扱うため）。
- 保存範囲：ブラウザのローカル保存のみ。未設定時のデフォルトは `standard`。不正な保存値は `standard` へ戻す。ローカル保存が利用できない環境でも `standard` として動作を継続し、ゲームを停止させない。
- 設定タイミング：ロビー入室時に選択可能、ゲーム中も常時メニューから変更可能。変更は同一ブラウザ内へ即時反映し、会話画面を開いたままでも再通信・LLM 再実行なしで即時再描画する。
- 他プレイヤー・他端末・他ブラウザへは同期しない。
- 表示コンポーネントは `packages/ui` の汎用コンポーネントとして設計する（適用範囲の全体拡張は今回決定しない）。
- 読みが辞書にない語・一意に確定できない語は、かな中心表示でも漢字のまま残る可能性がある。これを「すべてひらがなになる機能」と誤認させないよう、設定説明文言に明記する。

## 16. マルチプレイ

複数プレイヤーが同じ NPC と同時に会話できる。会話セッションはプレイヤーごとに独立し、他プレイヤーの会話内容は自動表示しない。共有ボタンは MVP に含めない。よみやすさ設定もプレイヤー（ブラウザクライアント）単位で独立し、他プレイヤーの表示に影響しない。NPC の占有・待ち行列は設けない。結果画面では、当該ゲームセッション中にチーム全体が参照した出典を、`sourceId`で重複排除した一覧として表示する。誰がどの質問をしたか、質問文、回答文は表示しない。

## 17. RAG と承認済み情報

`approved = true` の知識のみ検索対象とする。`scenarioId`・`npcId`・`areaId`・`themeId`・`hintLevel` でメタデータフィルタしてから検索する。検索結果がない、スコアが閾値未満、または担当テーマ外の場合は LLM の一般知識を使用しない。詳細は [`dialogue-ai-design.md`](./dialogue-ai-design.md) を参照。

## 18. 安全性

自由入力は最大 100 文字。回答は最大 120 文字（基準本文、ふりがな除く）。不適切な質問には内容へ踏み込まず、短く回答を拒否する。個人情報を入力しないよう必要に応じて案内し、入力された個人情報を回答内で繰り返さない。プレイヤー名やゲーム外情報を LLM へ渡さない。質問文・回答文を永続ログへ保存しない。NPC は登録・承認された知識以外の事実を作らない。LLM は HTML・ルビマークアップを生成しない。クライアントは生 HTML 描画（`dangerouslySetInnerHTML` 等）を行わない。実際の防災判断・避難判断として利用できると誤認させない。

## 19. 匿名分析

NPC の有効性をゲーム改善と研究・実験の両方で評価するため、会話本文を含まない匿名データを記録する。プレイヤー単位では、一時的な匿名プレイヤー ID、NPC に話しかけた回数、会話した NPC ID、使用した質問候補 ID、自由入力を使用した回数、使用したヒントレベル、NPC 会話に使用した合計時間、NPC 利用後に配置した土木技術を記録する。チーム・ゲームセッション単位では、匿名ゲームセッション ID、NPC 機能の有効・無効、シナリオ ID、最終被災度、使用予算、配置した土木技術、クリア・失敗を記録する。プレイヤー名、質問文、回答文、入力された個人情報は保存しない。**`readingLevel` の選択状況は現時点では匿名分析データへ含めない。** 読む力に関連する設定であるため、収集する場合は収集目的・保存期間・同意方法を別 Issue で決定し、人間の承認を得た上で追加する。出力はサーバー管理者だけが CLI コマンドから行い、CSV と JSON の両形式に対応する。認証なしの公開ダウンロード画面・API は作成しない。
