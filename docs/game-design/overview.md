# CivilCraft — ゲーム概要

## 概要

CivilCraft は、土木工学の役割や面白さを、ゲームを通じて直感的に学べる **1 人〜複数人で遊べるブラウザ向けゲーム** です。

プレイヤーは、河川氾濫の危険がある街を舞台に、堤防、遊水地、排水機場、護岸、河道掘削などの土木技術を適切な場所へ配置し、大雨などの災害から街を守ります。MVP では大雨のみを対象とし、台風は将来追加します。

舞台は **福島県郡山市の阿武隈川** をモデルとした地域です。実在する河川改修や治水対策の文脈を参考に、現実の防災課題とつながりのある体験を目指します（詳細は [舞台設定](../civil-engineering/setting.md)）。

ゲーム画面はマインクラフトのようなボクセル表現を採用しますが、Minecraft 本体は使用しません。オープンソース技術を活用して独自に開発し、**スマートフォンのブラウザ**から QR コードまたは URL でアクセスし、**タップ操作**で遊べる体験を目指します（QR コードはルーム招待には使用しません）。操作の詳細は [ui-controls.md](./ui-controls.md) を参照。

---

## 背景

土木工学は、道路、橋、河川、上下水道、防災設備など、社会を支える重要な分野です。

一方で、完成したインフラは日常生活の中に自然に存在しているため、その役割や技術的な工夫は一般の人から見えにくいという課題があります。

CivilCraft では、プレイヤー自身が土木技術を選択し、設置場所や費用、効果を考えながら災害へ対応することで、土木工学が人々の生活や安全をどのように支えているのかを体験できるようにします。

---

## 目的

本プロジェクトの主な目的は、以下のとおりです。

- 土木工学の役割や社会的価値を分かりやすく伝える
- 治水や防災に関する興味を持つきっかけを作る
- 技術ごとの用途、効果、制約をゲーム体験として学べるようにする
- 地域の災害やインフラについて考える機会を提供する
- スマートフォンから気軽に参加できる教育コンテンツを実現する

---

## ゲームコンセプト

プレイヤーは、河川と市街地を含むマップ上で、限られた予算と時間を使って治水対策を行います。

**1 プレイの想定時間は 3 分**です（**準備 → 災害 → 結果**のみ。**ロビー**は含まない）。**ロビー**とは、ゲーム操作方法の説明・ゲーム説明・名前設定・ルーム作成や参加など、本編（準備以降）の前に行う区間です。

一定時間が経過すると災害が発生し、河川の水位が徐々に上昇します。MVP では大雨のみを発生させます。

プレイヤーは、災害が発生する前の**準備**と、災害発生中の**災害**フェーズの両方で施設を配置できます。施設ごとに建設時間があり、**建設中は効果を発揮せず、完成後に初めて効果が有効**になります。

詳細なルール（勝敗条件・予算・時間配分など）は [game-rules.md](./game-rules.md) を参照。

### 基本的なゲーム進行

1. マップと災害条件を確認する
2. マップ上を移動し、河川・住宅地・道路・低地などの地形を調査する
3. 土木技術を選択する
4. 予算内で適切な場所へ施設を配置する（建設開始）
5. 大雨などの災害が発生する
6. 河川水位や浸水範囲が変化する
7. 必要に応じて追加の対策を行う（災害中も配置可能）
8. 災害終了後に被害状況を確認する
9. 使用した技術や設置場所について振り返る（MVP でも結果画面で実施。より詳細な配置例の提示は Phase 4）

## マルチプレイ

本ゲームは、1 人でもプレイできます。複数人で協力して街を守るマルチプレイも想定しています。

MVP では 1 人から最大 4 人まで参加できます。

**ソロプレイ**ではルームを作成しません。ロビーで名前設定・ゲーム説明等を行い、読み込み完了後に本編を開始します。**マルチプレイ**ではロビーでルームを作成・一覧から参加し、**2 人以上**が揃った状態で作成者がゲーム開始を行います（1 人だけではマルチを開始できません。1 人プレイはソロモードを使用）。

QR コードはゲームへのアクセス（URL と併用）にのみ使用し、ルーム招待には使用しません。

### ソロプレイ

1 人で全 5 種類の土木技術を自由に使用できます。ロビーで名前設定・説明等を行い、ルームは作成しません。予算は個人に付与されます。

### マルチプレイ

- **全員が災害対応担当** — MVP では固定役割の割り当ては行いません
- **チーム全体で 5 種類すべての土木技術を網羅する** — ゲーム開始時に**ランダム**で割り当て（希望制ではない）
- **1 人が他より多く担当してもよい**（人数に応じて担当数は変動する。例：2 人時は 2+3、3 人時は 2+2+1）
- **予算はプレイヤーごとに個人の予算** — 各自の予算内で担当施設を配置します
- **ルーム作成者**がゲーム開始。**2 人以上**（最大 4 人）が揃ってから開始可能
- 被災度・勝敗は**チーム全体で 1 つ**
- 限られた 3 分の中で、予算・建設時間・担当施設を考慮しながら意思決定します

固定役割（現地調査担当・河川監視担当・施工担当など）の導入は将来検討とし、[game-rules.md](./game-rules.md) の TODO に記載しています。

マルチプレイを通じて、土木工事では技術だけでなく、情報共有、優先順位の判断、チームでの意思決定も重要であることを表現します。

## 評価システム

ゲーム終了後は、勝敗判定と複数の観点からプレイ内容を評価します。詳細は [game-rules.md](./game-rules.md) を参照。

### 勝敗条件

| 結果 | 条件 |
|------|------|
| **クリア（成功）** | 被災度がクリア閾値**未満**（MVP 既定値：5%。`packages/game-data/` で管理） |
| **失敗** | 被災度がクリア閾値**以上** |

### 評価項目

結果フェーズでは、以下の観点からプレイ内容を評価・表示します。
- 浸水した面積
- 使用した予算
- 残り予算
- 施設の配置場所
- 対策を実施したタイミング
- 土木技術の組み合わせ
- プレイヤー間の協力状況（**マルチプレイ時**。被災をどれだけ抑えられたか）

### TODO：スコア表示

スコアを 1 数値に集約するか、複数指標を並列表示するかは今後決定する（[game-rules.md](./game-rules.md) 参照）。

結果画面では、使用した土木技術の解説や振り返りを表示します（MVP）。より効果的な配置例の提示など詳細な振り返りは Phase 4 で拡充します。

失敗した場合でも、なぜ被害が発生したのかを理解できるようにし、再挑戦につながる設計を目指します。

## 対応環境

MVP では **スマートフォンの Web ブラウザ** での **タップ操作のみ** を想定します（[ui-controls.md](./ui-controls.md) 参照）。

タブレット・PC ブラウザでの表示・操作は MVP 対象外とし、Phase 5 以降で対応を検討します。

アプリのインストールを不要とし、QR コードまたは URL からゲームにアクセスできるようにします（QR コードはルーム招待には使用しません）。

**PWA 対応（ホーム画面への追加・オフラインキャッシュ）は MVP 対象外**です。Phase 5 以降の展望として検討します。

## 開発フェーズ

各フェーズの包含関係は **Phase 1 ⊂ Phase 2 ⊂ MVP** です。Phase 3 以降は MVP 完成後に段階的に追加する拡張機能です。

| フェーズ | 位置づけ |
|---------|---------|
| Phase 1 | 技術検証（3D 描画・WebSocket 接続など） |
| Phase 2 | 最小ゲーム（1 マップ・大雨・5 技術・ソロ → マルチ） |
| **MVP** | **Phase 1 + Phase 2 の成果物を統合した初回リリース版** |
| Phase 3 以降 | MVP 以降の拡張（UX 強化・教育深化・運用） |

### マルチプレイ対応の段階的導入

**1 人で遊べる段階から徐々にマルチプレイ対応**していきます。各フェーズ完了時点で動作する範囲は以下のとおりです。

| 完了時点 | プレイ可能な内容 |
|---------|----------------|
| **Phase 1 完了** | 1 人でマップ上を移動し、施設を配置できるプロトタイプ（ゲームループ・災害シミュレーションは未実装） |
| **Phase 2 前半** | 1 人でゲームを完走できる（大雨・浸水判定・被災度・評価の表示まで） |
| **Phase 2 後半** | マルチ基盤（2〜4 人・ルーム・同期・開始直前読み込み） |
| **MVP** | Phase 1 + Phase 2 + 全ルール統合・初回リリース品質 |

Phase 1 では WebSocket 接続の基盤を整えますが、複数プレイヤーの同期は Phase 2 以降で段階的に実装します。

### Phase 1：技術検証

- スマートフォンでの 3D 描画確認
- ボクセル地形の表示
- プレイヤー移動
- タップ操作による施設配置
- Go と WebSocket による接続（サーバー接続基盤）
- **完了時点：1 人で移動・配置できるプロトタイプ**

### Phase 2：最小ゲーム実装

Phase 1 の技術基盤の上に、プレイ可能な最小ゲームを構築します。前半でソロ完走、後半でマルチプレイ機能を追加します。

**ソロプレイ（Phase 2 前半）**

- 1 つのマップ
- 1 種類の災害（大雨）
- 5 種類の土木技術（堤防、遊水地、排水機場、護岸、河道掘削）
- 河川水位の上昇
- 簡易的な浸水判定
- ゲーム開始と終了
- 被災度・評価の表示

**マルチプレイ（Phase 2 後半）** — マルチの技術基盤

- 複数プレイヤーの位置同期
- 2 人から最大 4 人まで（2 人未満では開始不可）
- ルーム作成（誰でも作成可能）・ルーム一覧からの参加
- 複数プレイヤーによる施設配置の同期
- ゲーム開始直前のデータ読み込み
- ルーム作成者によるゲーム開始

**MVP** — Phase 2 後半に加え、初回リリースに必要な統合・調整

- ソロ／マルチ全ルールの統合（ランダム技術割当、個人予算、被災度勝敗、ロビーフロー）
- クリア閾値等のマスターデータ化（`packages/game-data/`）
- 1 プレイ 3 分・結果フェーズでの評価・振り返り
- 初回公開に必要な UX・品質の調整

### Phase 3：マルチプレイ UX・耐障害性の強化

**基本のマルチプレイ（2〜4 人・ルーム・同期）は MVP に含まれます。** 本フェーズは、その上に UX と耐障害性を追加する拡張です。MVP で実装済みのルーム作成・一覧参加・最大 4 人プレイ・施設配置同期を土台に、以下を追加します。

- ルーム一覧・参加 UI の強化
- 再接続
- 切断処理
- ゲーム状態の復元

### Phase 4：教育要素の追加

MVP の「各技術の短い解説」を拡張し、学習体験を深めます。MVP との差分は以下のとおりです。

| 項目 | MVP | Phase 4 |
|------|-----|---------|
| 技術解説 | 選択・配置時の短い説明（1〜2 文程度） | 土木技術図鑑、技術ごとの詳細解説 |
| 結果の振り返り | 被災度・被害状況の表示、使用技術の振り返り | より効果的な配置例の提示、詳細な振り返り |
| 災害の理解 | なし | 災害発生理由の説明 |
| 地域学習 | なし | 阿武隈川の事例紹介 |
| オンボーディング | なし | 初心者向けチュートリアル |

### Phase 5：公開・運用

MVP 以降の公開・運用フェーズです。以下は MVP 対象外の項目を含みます。

- タブレット・PC ブラウザ対応
- PWA 対応（MVP 対象外・本フェーズで検討）
- AWS へのデプロイ
- CI/CD
- 監視
- ログ収集
- 利用者アンケート
- ゲームバランスの改善

## MVP

最初に開発する MVP は、Phase 1（技術検証）と Phase 2（最小ゲーム実装）の成果を統合した初回リリース版です。以下の機能に絞ります。

- 1 つの河川マップ（構成は [舞台設定](../civil-engineering/setting.md) 参照）
- 1 人から最大 4 人までプレイ可能（**ソロ：1 人**／**マルチ：2〜4 人**、ルーム作成・一覧参加、作成者が開始）
- プレイヤー移動
- 堤防、遊水地、排水機場、護岸、河道掘削の配置（5 種類）
- 複数プレイヤーによる施設配置の同期（全参加者が同時に施設を配置可能）
- マルチプレイ時：チーム全体で 5 種類を網羅するようランダム割り当て、プレイヤーごとの個人予算
- 一定時間後の大雨発生（台風は含まない）
- 河川水位の上昇
- 簡易的な浸水判定
- 被害状況と被災度の表示（クリア条件：被災度がクリア閾値未満。閾値は `packages/game-data/` で管理）
- 各技術の短い解説（選択・配置時の簡易説明。図鑑や詳細解説は Phase 4）
- 初期予算・建設費用・維持費によるコスト管理
- 施設ごとの建設時間（災害中も配置可能）
- 1 プレイ 3 分（準備・災害・結果。秒数配分は `packages/game-data/rules/game-timing.json` で管理。ロビーは含まない）

MVP では台風やその他の災害種別は実装しません。Phase 3 以降で、ルーム UI 強化・再接続・切断処理・ゲーム状態の復元などを追加します。Phase 4 以降で、図鑑・詳細解説・配置例提示・チュートリアルなどの教育要素を拡充します。

初期段階では、複雑な流体シミュレーションや大規模なワールド生成は行いません。

まずは「どこに何を置くかによって結果が変化する」という、ゲームの中心的な体験を完成させます。

## 将来的な展望

本ゲームのコアは**河川・浸水・治水**です。地震・津波・土砂災害・道路寸断・橋梁損傷など、コア外の災害メカニクスは実装しません。

将来的には、阿武隈川以外の河川や災害も追加し、複数の地域に対応できるゲームへ発展させます。展望に挙げる拡張も、河川・浸水・治水のコア内に収めます。

想定する拡張例は以下のとおりです。

- 台風
- 地域ごとのオリジナルマップ
- 学校やイベント向けの体験モード
- 管理画面からのシナリオ作成
- 自治体や教育機関との連携
- PWA 対応（ホーム画面追加・キャッシュ）

最終的には、ゲームを楽しむだけでなく、地域の防災やインフラについて考えるきっかけとなる教育プラットフォームを目指します。

---

## 注意事項

本ゲームは、土木工学や防災に関する理解を促進するための教育・体験コンテンツです。

ゲーム内の災害挙動、施設効果、工事費用、地形、被害状況は、遊びやすさや理解しやすさを優先して簡略化する場合があります。

実際の防災計画、河川整備、避難行動、土木設計の判断には使用できません。
