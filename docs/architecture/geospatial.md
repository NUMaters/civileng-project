# 地理空間アーキテクチャ

CesiumJS、国土地理院データ、ゲーム用シミュレーションデータの責務と座標方針を定義する。

## 対象範囲

MVP では福島県郡山市の日本大学工学部周辺を流れる阿武隈川を対象とする。対象範囲の境界、初期カメラ位置、標高範囲は現地確認とデータ検証後に `packages/game-data/maps/koriyama/` へ定義する。

## 責務の分離

| 領域             | 責務                                                       |
| ---------------- | ---------------------------------------------------------- |
| CesiumJS         | 地図・地形・施設の表示、カメラ操作、ドロップ／ピック位置の取得 |
| 国土地理院データ | 背景地図と、採用を決定した場合の標高データの提供           |
| web              | 入力候補の表示、地理座標への変換、サーバー状態の描画       |
| server           | 配置可否、予算、ゲーム進行、水位、浸水、被災度の権威状態   |
| game-data        | 対象範囲、施設配置可能領域、河川領域、計算グリッドとの対応 |

CesiumJS の描画結果をゲーム判定の正としない。表示用地形の解像度や取得状況に左右されず、同じ入力から同じ結果を再現できるよう、サーバーは簡略化したゲーム用データで判定する。

## 座標

- 永続化・REST・WebSocketでは `longitude`、`latitude`、`height` を使用する
- 経度・緯度の単位は度、標高の単位はメートルとする
- 経度は `-180..180`、緯度は `-90..90` の範囲で検証する
- クライアント内部では CesiumJS の `Cartesian3` を使用できるが、通信境界では地理座標へ変換する
- 国土地理院の日本国内タイルは JGD2011、CesiumJS は WGS84 楕円体を基準とするため、MVPで許容する位置精度を実測して記録する
- 浸水計算では対象地域に固定したローカル座標またはグリッドへ変換する。変換処理はサーバー側で一元管理する

既存の `Position { x, y, z }` はプロトタイプ用であり、地理座標型への移行後は通信に使用しない。

## 地図・標高データ

背景は地理院タイルの全国最新写真（シームレス）を既定とし、地名や道路を確認しやすい標準地図へ画面上で切り替えられるようにする。CesiumJS の URL テンプレート対応 Imagery Provider から XYZ タイルとして読み込む。

### リアリティの段階

| 段階 | 表示内容                                         | 状態                                         |
| ---- | ------------------------------------------------ | -------------------------------------------- |
| 1    | 航空写真、斜めカメラ、立体施設、影・大気表現     | 実装済み                                     |
| 2    | 国土地理院DEMを変換した表示用Terrain             | ブラウザ内変換方式で実装済み                 |
| 3    | PLATEAU LOD1建物を3D Tilesとして表示             | 公式全国配信を利用したプロトタイプを実装済み |
| 4    | 専用glTF施設、工事アニメーション、水面・浸水表現 | 複合基本形状まで実装、専用glTFは未実装       |

現在のプロトタイプは、国土地理院の標高PNGをブラウザ内で32×32のHeightmapへ変換し、`CustomHeightmapTerrainProvider`へ渡す。地表タップにはTerrainとの交点を使用する。ズーム14を超える要求では、標高タイルの最大ズーム14を親タイルとして部分サンプリングする。

建物は郡山市公式 3D Tiles ZIP 内の **`bldg_texture`**（写真テクスチャ付き）を `apps/web/public/plateau/koriyama-bldg-texture/` に展開して表示する（`pnpm --filter @civilcraft/web fetch:plateau`）。PLATEAU VIEW の `07203-bldg-lod2-texture-latest` は CMS 上のテクスチャ無し LOD2 に解決されるため使わない。ローカル展開が無い場合のみ VIEW の LOD1 へフォールバックする。テクスチャを消さないよう `Cesium3DTileStyle` の単色上書きは行わない。

初期カメラは日本大学工学部周辺の阿武隈川河道上（おおよそ 140.3837°E, 37.3655°N）。カメラは画面中央の注視点が川中心線から約 950 m 以内に収まるよう操作終了時に補正し（位置クランプはしない）、施設配置は中心線 ± 約 75 m の河道＋河岸コリドー上のみ許可する（市街地・広い氾濫原は不可。判定は `riverPlacement.ts`）。配置可能帯は薄いシアンの Entity コリドーで示し、本川水面は別レイヤの Water マテリアルで描く。写真テクスチャは 2020 年度整備の LOD2 範囲に集中しており、工学部直近は無地のグレー箱が多くなる。建物タイルは `CustomShader`（UNLIT）で両立する。画面空間の色の変化（`dFdx`/`dFdy`）で写真テクスチャ面と無地面を判別し、テクスチャ面はそのまま明るく、無地面は疑似陰影付きのグレー箱として描く。全国 `all-bldg-lod1-2025` には郡山が含まれないため使用しない。地形は **PLATEAU-Terrain**（`https://tile.plateauview.mlit.go.jp/terrain/`、ジオイド補正済み楕円体高）を優先し、失敗時のみ地理院 DEM + 郡山周辺の概算ジオイド高（約 +39.5 m）へフォールバックする。正標高のまま DEM を渡すと建物が浮く。運用版では対象範囲の抽出配信と性能を比較する。表示用3D建物をサーバーの浸水判定へ直接流用しない。

標高の運用方式については次を比較して決定する。

1. 国土地理院の標高タイルを前処理し、対象地域のゲーム用標高グリッドを生成する
2. Cesium対応のTerrainデータを別途用意し、表示用に使用する
3. MVPでは平面または簡略地形を表示し、計算用標高だけを国土地理院データから生成する

国土地理院の標高PNGはCesium Terrain形式ではないため、必ず高さ配列またはTerrain形式へ変換する。現在のランタイム変換は技術検証用であり、運用時はCDN配信、永続キャッシュ、対象範囲外の扱い、欠損値補間を追加検証する。

## 配置フロー

1. クライアントが建設ドックから施設をドラッグし、地表ドロップ位置の地理座標を得る（向きはカメラ heading）
2. 対象範囲内・河道／河岸上かをクライアントで仮判定し、通れば仮配置（プレビュー）を表示する（市街地は拒否。この時点では予算未消費）
3. プレイヤーが向きを調整したうえで確定したとき、施設種別・地理座標・向きをサーバーへ送る（プロトタイプはクライアント確定。キャンセル時は送信しない）
4. サーバーが範囲、地形、重複、担当、予算を検証する
5. サーバーが確定した施設IDと位置・向きを全クライアントへ配信する
6. クライアントが確定状態をCesiumJS上へ描画する（向き・位置の調整は仮配置中のみ。確定後は固定）

## 河道と氾濫原

中心線 `ABUKUMA_RIVER_CENTERLINE` は南→北順（index 0 が下流側）。阿武隈川はこの区間で概ね南へ流れるため、流向ストリークは北→南へアニメーションする。

| レイヤ | 範囲の目安 | 用途 |
|--------|------------|------|
| 本川水面 | 中心線コリドー 約 78〜146 m 幅 | 平常時〜増水の見た目（Water マテリアル＋下流向きストリーク） |
| 配置可能域 | 中心線片岸 **75 m**（全幅約 150 m） | 河道＋河岸への施設ドロップ。市街地は拒否 |
| 弱点・越水 | 既知5点＋中心線サンプル。DEM岸高で重み付け | 低い岸・湾曲部が先に溢れる |
| 施設効果 | 河岸距離・向き・標高・弱点近接 | `hydraulicPlacement` / `floodSimulation` |
| **高さ場浸水** | 決壊点から格子上で水位伝播（浅水近似） | `inundationField` / `inundationVisualization` |
| **氾濫寸前の氾濫原** | 中心線片岸 **200 m**（全幅約 400 m） | 水位 3.6 m 超で可視化開始。通常時は非表示 |
| **越水拡大氾濫原** | 中心線片岸最大 **320 m**（全幅約 640 m） | 越水量に応じて外側へ拡大 |

氾濫原ポリゴンは `ABUKUMA_RIVER_CENTERLINE` から生成する（`buildCenterlineCorridorRing`）。定数は `floodplainExtent.ts`、描画は `nearOverflowFloodplain.ts`。

浸水表示は決壊地点（`overflowSites`）を起点に、流出方向へプルーム・ストリークを出しつつ、簡易浅水の高さ場（`inundationField`）で低地へ広がる水深バンドを描く。固定座標の市街地浸水ゾーンは使わない。

## 性能方針

- スマートフォン実機を基準に計測する
- 表示範囲、最大ズーム、施設数、同時エフェクト数を制限可能にする
- Reactの再レンダーとCesiumJSの描画ループを分離する
- Cesium Viewerを画面遷移ごとに重複生成しない
- タイル取得失敗時にもゲームUIが操作不能にならないよう状態を分ける

## 利用条件と出典

- 使用する地理院タイルごとに地理院タイル一覧の区分と備考を確認する
- 画面内または常時到達可能な箇所へ国土地理院の出典を表示する
- 加工した標高・地図データには加工した旨と元データを明示する
- 他機関由来のタイルを追加する場合は、各提供元の条件も確認する
- タイルを一括取得・再配布する設計は、利用条件と配信負荷を確認するまで採用しない
