# 技術スタック

## フロントエンド

| 技術 | 用途 |
|------|------|
| TypeScript | 型安全なアプリケーション開発 |
| Vite | ビルド・開発サーバー |
| React | UI フレームワーク |
| CesiumJS | 実在地域の 3D 地理空間表示、カメラ操作、地表の位置取得 |
| WebGL | 3D レンダリング |
| WebSocket | リアルタイム通信 |
| PWA | ホーム画面追加・オフラインキャッシュ（MVP 対象外・Phase 5 以降で検討） |
| HTML / CSS | マークアップ・スタイル |

フロントエンドでは、国土地理院の地理院タイルを背景地図として CesiumJS で表示し、カメラ操作、施設配置、UI 表示、サーバーとのリアルタイム通信を担当します。対象地域は福島県郡山市の日本大学工学部周辺を流れる阿武隈川とします。

CesiumJS は表示と入力に使用し、配置可否、水位、浸水、被災度などのゲーム判定は担当しません。詳細は [地理空間アーキテクチャ](./geospatial.md) を参照してください。

## バックエンド

| 技術 | 用途 |
|------|------|
| Go | バックエンドアプリケーション |
| REST API | ゲーム前後の処理 |
| WebSocket | ゲーム中のリアルタイム処理 |
| PostgreSQL | 永続データ |
| Redis | セッション・キャッシュ |

バックエンドでは、以下の処理を担当します。

- プレイヤー管理
- ルーム管理
- ゲーム状態管理
- リアルタイム同期
- 土木施設の設置判定
- 災害イベントの進行
- 水位や浸水範囲の計算
- 被災度の計算

初期段階では、モジュラーモノリスとして単一のバックエンドアプリケーションを構築します。

将来的には、アクセス数や負荷特性に応じて、API サーバーとゲームサーバーを分離できる設計を目指します。

## インフラ

初期構成では、以下のサービスや技術を候補とします。

| 技術 | 用途 |
|------|------|
| Docker / Docker Compose | ローカル・コンテナ実行 |
| Cloudflare Pages | ソロ静的 Web 公開（案α・低コスト） |
| AWS | クラウド基盤（マルチ・永続化が必要な段階） |
| Amazon ECS | コンテナオーケストレーション |
| Amazon RDS | マネージド PostgreSQL |
| Amazon ElastiCache | マネージド Redis |
| Amazon S3 | アセット・静的ファイル |
| Amazon CloudFront | CDN |
| Terraform | インフラ as Code |
| GitHub Actions | CI/CD |

開発初期はローカル環境や低コストなクラウド環境で動作させ、利用者数に応じて段階的に拡張します。

ソロ静的公開（案α）は **Cloudflare Pages** を推奨する。Git 連携時の本番ブランチは `develop`（現状の `main` はモノレポ未整備）。手順は [deploy-cloudflare-pages.md](../development/deploy-cloudflare-pages.md)。
