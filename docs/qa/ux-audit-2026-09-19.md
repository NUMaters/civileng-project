# CivilCraft 実機 UX 総合監査（2026-09-19）

## 実施条件

- ブラウザ: Codex In-app Browser
- 実測 viewport: 685 × 965 CSS px、devicePixelRatio 2（縦長表示）
- URL: `http://localhost:5174/`
- 操作: クリック、ドラッグ、Tab / Escape / Enter、フェーズ進行、結果確認
- 導線: タイトル → メニュー → 遊び方 → ゲーム開始 → 準備 → 大雨 → 結果 → マップ確認 → メニュー

## 既存 QA で修正済み

- CC-001: ゲーム開始直後の `Cannot access 'C' before initialization`
- CC-002: 初回メニューで遊び方が自動表示される
- CC-003: 遊び方モーダルから背面へフォーカスが逃げる
- CC-004: エラーバウンダリが内部例外を露出する
- CC-005: favicon の 404

## 今回の課題

### UX-001（P1 / 視認性）結果マップの色の意味がその場で分からない

「マップを確認」で洪水・影響範囲が青／橙のオーバーレイで表示されるが、凡例や説明がない。結果の振り返りと再挑戦の手がかりが弱い。

改善: 浸水・施設の影響圏・決壊／注意地点の凡例を結果マップへ表示する。

### UX-002（P1 / 操作性）ドラッグ配置の誘導が弱い

建設ドックの説明は「上へドラッグ → 黄色い帯」だが、ドラッグ前に帯が見えず、配置地点の発見を試行錯誤に頼る。キーボード配置は仮配置・向き調整・確定まで到達できる。

改善: 選択施設と配置可能帯を常時連動させ、ドラッグ成功／失敗の短いフィードバックを出す。キーボード配置は地図中央への仮配置であることを明記する。

### UX-003（P1 / 快適性）縦長画面で建設ドックが地図を大きく隠す

685 × 965 では建設ドックと選択施設の説明パネルが重なり、画面下約 230 px が UI になる。配置候補と影響圏を同時に見づらい。

改善: モバイルは詳細説明を折りたたみ、ドックの最小高と仮配置中の確定バーを優先する。

### UX-004（P2 / 情報設計）Phase 表示が縦に詰まる

Phase 名が複数行に折り返され、残り時間・警戒レベル・操作ボタンの優先順位が競合する。モバイルは `準備 / 大雨 / 結果` を主ラベルにする。

### UX-005（P2 / フィードバック）結果の再挑戦理由が抽象的

施設数や適所への配置を促す説明はあるが、未対策の弱点・効果の高かった施設・位置のどれを変えるべきかは結果画面だけでは判断しづらい。

### UX-006（P2 / 安全性）中断・メニュー復帰で状態が即時破棄される

プレイ中の中断から確認なしでメニューへ戻る。破棄操作であることを明示し、続ける／メニューへ戻るを選べるようにする。

## 良かった点

- タイトルで目的・3 ステップ・所要時間が一画面で理解できる。
- 遊び方モーダルは施設の役割・仕組み・現実用途を持ち、Tab 循環と Escape が機能する。
- 準備 → 大雨 → 結果 → マップ確認 → メニュー復帰を通して操作できる。
- 施設選択 → 仮配置 → 向き調整 → 確定で安全度が上がり、予算不足の施設は無効化される。
