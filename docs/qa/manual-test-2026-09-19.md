## 課題一覧

### CC-001（P0）ゲーム開始直後にクラッシュする — 修正済み

**再現手順**

1. 「はじめる」
2. 「シングルプレイ」
3. 「ゲームスタート」

**実際の結果**

「画面の表示に失敗しました」となり、`Cannot access 'C' before initialization` が表示され、地図・準備フェーズへ進めない。別タブでも同じエラーを再現した。

**原因**

`GameplayApp` の `paused` state を宣言する前に `useFloodSimulation(..., inGame && !paused)` で参照していた。ビルド後の変数名 `C` がエラーメッセージに現れていた。

**対応**

`paused` の初期化を洪水シミュレーション hook より前へ移動した。

### CC-002（P1）初回メニューで遊び方が自動表示される — 修正済み

**実際の結果**

初回に「はじめる」を押すと、モード選択より先に遊び方モーダルが表示された。仕様上は「遊び方はボタンから開く（自動表示しない）」ため、最初の意思決定を遮っている。

**対応**

タイトルからメニューへ入る際は常にモーダルを閉じた状態にし、「遊び方」ボタンからのみ開くようにした。

### CC-003（P1 / アクセシビリティ）遊び方モーダルから背面 UI にフォーカスが逃げる — 修正済み

**実際の結果**

モーダル表示中に Tab を押すと背面の「シングルプレイ」や「閉じる」にフォーカスが移動し、Enter で背面のシングルプレイ選択まで実行できた。`aria-modal="true"` の宣言と実際のキーボード操作が一致していない。

**対応**

- モーダル表示時に最初の閉じるボタンへフォーカスを移動
- Tab / Shift+Tab をモーダル内で循環
- Escape と背景クリックで閉じる既存動作を維持
- 閉じた後は元の起点へフォーカスを復元

### CC-004（P2）エラーバウンダリが内部実装の例外文字列をユーザーに露出する — 修正済み

**実際の結果**

`Cannot access 'C' before initialization` のような minify 後の内部変数名がそのまま表示され、一般ユーザーには原因も対処も分からない。また「開発サーバーを再起動してください」という開発者向け文言が本番画面に出ていた。

**対応**

画面には「ゲーム画面を読み込めませんでした」「ページを再読み込みして、もう一度お試しください」と表示し、詳細な例外は既存の `console.error` に限定した。

### CC-005（P2）favicon が存在せず 404 になる — 修正済み

**実際の結果**

ブラウザが `/favicon.ico` を要求し 404 になっていた。

**対応**

CivilCraft の簡易 SVG favicon を追加し、`index.html` から明示的に参照した。

### CC-006（P1 / 検証ブロッカー）ゲーム本編の操作・楽しさを確認できない — 再検証済み

CC-001 修正後に再検証し、地図・準備・大雨・結果・自由閲覧まで到達できることを確認した。

- Cesium 地図の初期表示、カメラ移動、地形・建物の読み込み
- 建設ドックの表示、施設選択、準備スキップ
- 予算、建設時間、弱点マーカー、影響圏の分かりやすさ
- 準備 → 大雨 → 結果 → 自由閲覧の時間同期
- 浸水表現、雨勢、水位、被災度、勝敗・振り返りの納得感

ただし、ポインタードラッグによる施設配置は自動操作環境で確実な確定まで再現できず、実機タッチ／マウスで追加確認が必要。配置導線がドラッグ操作に依存しているため、キーボード利用者向けの代替操作も別 Issue（CC-009）として扱う。

### CC-007（P2 / 開発環境）標準の開発サーバー起動が不安定

今回の検証では `pnpm` / Corepack が `packageManager` の読み込みで `ETIMEDOUT` になり、通常の `pnpm dev:web` を利用できなかった。また 5173 番ポートは別プロセスが使用していたため、5174 番で既存ビルドを配信して検証した。

これはアプリ UI の欠陥とは切り分けるが、再現確認の入口として開発者体験を阻害する。依存ツールチェーンのローカルキャッシュ、ポート自動選択、起動手順の改善を別 Issue として扱う。

### CC-008（P2 / プロダクト未実装）マルチプレイは選択不可

メニューには「準備中」「近日開放」と表示され、ボタンは disabled。現状の仕様どおりだが、複数人プレイを訴求する場合は、開放時期または代替の遊び方を明示する必要がある。

### CC-009（P1 / アクセシビリティ）施設配置がポインタードラッグに依存する — 修正済み

建設ドックの施設カードはキーボードで選択できるが、配置確定は「上へドラッグ → 黄色い帯」に限定されている。キーボードやドラッグが苦手な利用者には、選択後に地図上の配置位置を指定する代替導線がない。

**対応**: 選択中カードに「キーボードで配置」を追加した。河道上に仮配置し、既存の矢印キーで位置を調整、Enterで確定、Escapeでキャンセルできる。CUA実操作で、ボタン→矢印キー→Enterの一連の確定と予算反映を確認した。

### CC-010（P1 / 操作性）ゲーム途中に中断してメニューへ戻る導線がない — 修正済み

準備／大雨中は、結果まで待つかブラウザを再読み込みしないとゲームを終了できない。長時間離席や誤って開始した場合に復帰手段がない。

**対応**: ミッションパネルに「中断」ボタンを追加し、いつでもメニューへ戻れるようにした。

### CC-011（P2 / 情報設計）結果画面の英語バッジが本文と混在する — 修正済み

結果画面は本文・ボタンが日本語なのに、状態バッジだけ `CLEAR` / `FAILED` となる。意味は推測できるが、対象ユーザー向けの言語統一が不十分。

**対応**: 結果画面とマップ確認バーのバッジを `成功` / `失敗` に統一した。

## 良かった点

- タイトル画面の目的・所要時間・3 ステップが一画面で理解できる。
- メニューのシングルプレイ説明に準備時間、大雨時間、クリア条件が含まれている。
- 遊び方の施設ガイドは accordion、Escape、背景クリック、了解ボタンで閉じられる。
- 遊び方の各施設に役割・仕組み・現実での用途があり、学習コンテンツとしての方向性は良い。
- タイトルとメニューの Tab / Enter 操作は機能した。
